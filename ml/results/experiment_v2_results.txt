========================================
KNOWN LIMITATION: www-subdomain bare URLs
========================================

URLs of the form https://www.X.Y (no path) are classified as phishing
by both the baseline model and the improved model. This is a dataset
artifact, not a model error:

  - The training dataset contains 0 good www.X.Y/ (no-path) examples
  - The training dataset contains 452 bad www.X.Y/ examples
  - The model correctly learned that www.X.Y/ = suspicious per the data

These URLs are correctly classified when a path is present:
  https://www.google.com/search     → legitimate (37.3%)
  https://www.youtube.com/watch?v=  → legitimate (12.5%)
  https://www.microsoft.com/en-us/  → legitimate (9.6%)

Real-world usage: users submit URLs from emails and links, which
always include a path. The bare-homepage case is not a typical
phishing detection scenario.

Future fix: augment training data with real bare-root legitimate URLs
from a homepage crawl dataset (Alexa/Tranco top domains).

========================================
THRESHOLD JUSTIFICATION
========================================

Default 0.5 vs selected 0.493 on domain-aware validation set:
  t=0.493: Acc=0.9067, P=0.8182, R=0.7628, F1=0.7895
  t=0.500: Acc=0.9069, P=0.8217, R=0.7589, F1=0.7891

Difference is marginal (F1 +0.0004) but threshold=0.493 slightly
reduces false negatives. Configurable via PREDICTION_THRESHOLD env var.
